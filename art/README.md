# art/ — 그림 넣는 곳

앱이 **실행 중에 이 폴더를 직접 읽는다.** 파일을 바꾸고 앱 상단의 `↺` 버튼만 누르면
바로 반영된다. `flutter run`을 다시 할 필요 없다.

파일이 없으면 그 자리에 회색 플레이스홀더가 뜬다. 그러니 한 장씩 채워 넣으면서
확인해도 되고, 다 그린 뒤에 한꺼번에 넣어도 된다.

```
art/
├── desk/
│   └── background.png     책상 배경 (320×240 화면에 꽉 차게 그려진다)
├── char/                  모든 프로젝트가 공유하는 기본 캐릭터
│   ├── base.png           ← 상태 그림이 없을 때 대신 쓰는 한 장
│   ├── idle.png           대기
│   ├── thinking.png       생각 중
│   ├── working.png        작업 중
│   ├── waiting.png        승인 대기
│   ├── bored.png          심심함
│   └── done.png           완료
├── chars/                 캐릭터 세트 — 두 번째 캐릭터부터 여기에 넣는다
│   └── 수도승/
│       ├── base.png       한 장만 넣어도 그 세트가 된다
│       └── working.png    있는 상태만 갈아끼운다
├── hats/                  계층 모자 — 캐릭터 머리 위에 코드가 얹는다
│   ├── director.png       이사 (64×32, 투명, 아랫줄 가운데가 머리 윗줄에 닿는다)
│   ├── manager.png        팀장
│   └── director_working.png  ← 상태 이름을 붙이면 그 상태에서만 이 모자
├── office/                사무실 층 배경 (대시보드 사무실 칸)
│   ├── floor.png          팀 층 — 444×172, 바닥선 y=138
│   └── boss_evening.png   ← 칸·시간대를 붙이면 그때만 이 그림
├── projects/              특정 프로젝트만 다른 캐릭터를 쓰고 싶을 때
│   └── rpg_habit/
│       └── working.png    ← 이 프로젝트의 '작업 중'만 이 그림으로 바뀐다
└── refs/                  ⛔ 앱이 읽지 않는다 — 그림체 레퍼런스 보관용
```

## 사무실 층 배경 — `office/` (2026-09-18, 실측 규격)

대시보드 **사무실**은 빌딩이고 층 하나가 가로 한 줄이다. 그 층의 **벽 그림**이 여기 들어간다.
없으면 코드가 그린 벽·바닥·창문이 대신 나오므로, 한 장도 안 넣어도 화면은 멀쩡하다.

```
art/office/
├── floor.png            팀 층 — 시간대 그림이 없을 때 쓰는 한 장
├── floor_morning.png    아침 (06–12시)
├── floor_afternoon.png  오후 (12–18시)
├── floor_evening.png    저녁 (18–06시)
├── boss.png             이사 층(맨 위, R) — 없으면 floor 쪽으로 떨어진다
├── boss_morning.png
├── boss_afternoon.png
└── boss_evening.png
```

### 크기 — **222 × 104 px** (1배 그대로, 2026-09-18 대표 결정)

화면에 그 크기로 깔린다. 캐릭터가 64px 원본 그대로 서므로 **그림 1픽셀 = 캐릭터 1픽셀**이다
(레티나에서는 둘 다 화면 2점). 크기를 바꾸고 싶으면 `layout.json`의 `height`를 같이 고친다.

| 무엇 | 값 (px) |
|---|---|
| 그림 전체 | **222 × 104** |
| **바닥선**(캐릭터가 서는 선) | 위에서 **78** (아래에서 26) |
| 책상 띠(이름이 앉는 곳) | y 78 ~ 104 |
| 캐릭터 한 자리 | 폭 **56**, 한 층에 셋 |
| 창문 자리 | **48 × 28**, 오른쪽에서 8, 위에서 14 |
| 층수·팀 이름 글자 | 왼쪽 위 y 0 ~ 14 |

### 그림 한 장이 다 정한다 — `layout.json` (2026-09-18)

벽·책상·창문을 **한 장에 통째로** 그려도 된다. 그때 캐릭터가 어디에 서는지만 알려주면 된다.

```json
{ "height": 104, "floorLine": 78, "window": { "w": 48, "h": 28, "right": 8, "top": 14 } }
```

| 칸 | 뜻 |
|---|---|
| `height` | 층 한 칸의 높이(= 그림 세로) |
| `floorLine` | **캐릭터가 서는 선.** 그림 위에서부터 잰 값 |
| `window` | 창문 그림이 얹힐 자리. 창문을 벽에 같이 그렸으면 신경 안 써도 된다 |

- 이 파일을 고치고 앱의 `↺`만 누르면 **재빌드 없이** 반영된다.
- 캐릭터는 **64 × 64 원본 그대로**다(1픽셀 = 화면 2점). 이 값만 코드가 고정한다.
- `window_*.png`를 넣으면 그 그림이 창문 자리에 얹히고, **안 넣으면 벽 그림에 창문이 있다고 본다** —
  코드가 그리던 유리는 물러난다. 벽 그림도 없을 때만 코드가 벽·창문을 그린다.

### 그릴 때 지킬 것

### 그릴 때 지킬 것

- **바닥선(y=138)을 맞춘다.** 캐릭터가 그 선 위에 선다 — 어긋나면 사람이 공중에 뜨거나 바닥에 박힌다.
- **왼쪽 위 34px은 비워 둔다.** 층수(`3F`)와 팀 이름이 그 자리에 얹힌다.
- **왼쪽 절반은 얕게.** 캐릭터가 왼쪽부터 채워 앉는다(한 층에 넷). 무늬는 오른쪽에.
- **창문을 그림에 넣어도 된다.** 그러면 코드가 그리는 창문은 꺼 준다(말해 주면 한 줄로 끈다).
- 색은 **옅게**. 이름·층수가 그 위에 얹히므로 진하면 글자가 안 읽힌다.
- 투명을 써도 된다 — 뒤에 벽 색이 비친다.

### 시간대

아침 6–12 · 오후 12–18 · 저녁 18–6. 시간대 그림이 없으면 `floor.png` 한 장이 하루 종일 쓰이고,
창밖 색만 코드가 시간대에 따라 바꾼다.

## 캐릭터를 한 장만 그렸다면 — `base.png`

`char/base.png` 한 장만 넣으면 **일곱 상태가 전부 그 그림으로 뜬다.**
상태별 그림을 하나씩 채워 넣을 때마다 그 상태만 `base.png`를 밀어내고 바뀐다.
캐릭터를 하나부터 시작할 때 쓰라고 있는 규칙이다.

찾는 순서는 좁은 것부터다.

```
projects/<프로젝트>/<상태>.png  →  projects/<프로젝트>/base.png
                               →  char/<상태>.png  →  char/base.png
```

## 상태 7종

파일명은 아래 7개로 고정이다. 훅 이벤트와 1:1로 대응한다.

| 파일명 | 상태 | 언제 뜨나 |
|---|---|---|
| `idle.png` | 대기 | 세션이 막 시작됨 (`SessionStart`) |
| `thinking.png` | 생각 중 | 프롬프트를 넣은 직후 (`UserPromptSubmit`) |
| `working.png` | 작업 중 | 도구를 쓰는 중 (`PreToolUse`/`PostToolUse`) |
| `waiting.png` | 승인 대기 | 권한 승인·입력을 기다리며 멈춤 |
| `bored.png` | 심심함 | 할 일 없이 놀고 있음 (`idle_prompt`) |
| `error.png` | 문제 발생 | 도구 실패·응답 실패 (`PostToolUseFailure` 등) |
| `done.png` | 완료 | 작업이 끝남 (`Stop`) |

## 파일명 — 세 가지 형태를 다 읽는다

한 상태를 찾을 때 아래 순서로 본다. 먼저 찾은 것을 쓴다.

| 순서 | 형태 | 예 |
|---|---|---|
| 1 | `<상태>/` 폴더 안의 png 전부 (이름순) | `char/working/01.png` |
| 2 | `<상태>.png` | `char/working.png` |
| 3 | `*_<상태>.png` (접두어 아무거나) | `char/char_001_working.png` |

3번이 있어서 **캐릭터 세트 이름을 파일명 앞에 붙여도 된다.**
`char_001_working.png`, `char_001_base.png` 처럼 써도 그대로 읽힌다.

## 애니메이션 — 두 가지 방법

**가로 스프라이트 시트** (권장) — 가로가 세로의 정수배면 자동으로 잘라 순환 재생한다.

```
char_001_working.png   256×64  →  64×64 짜리 4프레임으로 잘림
```

**번호 파일** — `<상태>/` 폴더에 넣으면 이름순으로 재생한다.

```
char/
├── idle.png          ← 한 장짜리
└── working/          ← 여러 장짜리
    ├── 01.png
    ├── 02.png
    └── 03.png
```

둘 다 약 0.18초/프레임이다. `.png`만 읽는다.

## 반복 구간 — `anim.json`

시트의 일부만 반복시키고 싶을 때 `art/anim.json`에 적는다. **1번부터 세고 양끝을 포함한다.**

```json
{
  "working": "2-4"
}
```

- `2-4` → **1번은 상태에 들어올 때 한 번만 지나가는 인트로**, 그 뒤 2·3·4만 계속 돈다
- 적지 않은 상태는 전 프레임을 반복한다 (`idle`이 지금 그렇다)
- 재생 위치는 **상태가 바뀐 시점** 기준이다. 도구를 연달아 써도 인트로가 다시 튀지 않는다

앱 로그에서 제대로 읽혔는지 확인할 수 있다.

```
아트 로드: .../art | idle:4f working:4f(반복 2-4) base:1f | 배경 없음
```

## 규격

| 항목 | 값 | 비고 |
|---|---|---|
| 캐릭터 표시 높이 | 56px | 원본이 더 크면 비율 유지해서 줄인다 |
| 권장 원본 크기 | 64×64 또는 128×128 | 정수배로 줄어드는 크기가 덜 뭉갠다 |
| 배경 | 320×240 비율 | 화면을 덮게 잘린다 (`BoxFit.cover`) |
| 책상 상판 선 | **아래에서 26px** | 캐릭터가 이 선 위에 발을 딛는다 |
| 형식 | PNG, 투명 배경 | 캐릭터는 배경이 투명해야 책상 위에 얹힌다 |
| 아래 여백 | **신경 쓰지 않아도 된다** | 앱이 실제 그림 끝을 재서 상판에 맞춰 내려 그린다 |

확대·축소는 `FilterQuality.none`으로 처리한다. 픽셀이 뭉개지지 않고 각지게 커진다.

## 캐릭터 세트 — 프로젝트마다 다른 캐릭터

`art/chars/<세트이름>/` 에 그림을 넣으면 세트가 하나 생긴다.
위젯에서 **캐릭터를 우클릭 → 세트 이름을 고르면** 그 프로젝트만 그 캐릭터로 바뀐다.

```
art/chars/
├── 수도승/base.png        ← 한 장만 넣어도 된다
└── 로봇/
    ├── base.png
    └── working.png       ← 있는 상태만 갈아끼우고 나머지는 base
```

- 고른 세트는 `watched_projects.json`의 `char` 항목에 적힌다
- `art/char/`(기존)은 **기본** 세트다. 아무것도 고르지 않으면 이쪽을 쓴다
- 찾는 순서: `projects/<프로젝트>/` → 고른 세트 → 기본
- 하위 폴더의 임시 세션은 아래 **`staff`(사원)** 세트를 쓴다

## 계층 세 단계 — `director` · `manager` · `staff` (자동)

**이 세 이름만 특별하다.** 고르지 않아도 위젯이 알아서 물린다.
직급처럼 계층을 그림으로 가른다.

```
art/chars/
├── director/base.png     이사  ← 최상위 등록 (02_무위다라니)
├── manager/base.png      팀장  ← 하위로 등록한 프로젝트 (otaku_log 등)
└── staff/base.png        사원  ← 등록 안 한 폴더에서 띄운 세션 (otaku_log/lib)
```

- **한 장(`base.png`)만 넣어도 된다.** 상태별 그림은 있는 것만 갈아끼운다
- **없어도 된다.** 그림이 없으면 기본 캐릭터로 떨어져 지금과 똑같이 보인다.
  넣는 순간부터 그 단계만 달라진다
- 그 프로젝트에 세트를 **직접 골라 두었으면 사람이 고른 쪽이 이긴다**
- 크기는 세 단계가 **전부 똑같다.** 계층은 그림으로만 가른다 — 크기를
  건드리면 자리 계산이 흔들리고 책상 폭이 밀린다
- ⚠️ **단계는 셋뿐이다.** 등록을 더 깊이 해도 `manager`다. 단계가 늘면
  그림을 그만큼 더 그려야 하고 테마 한 벌이 무거워진다
- 테마를 만들 때 이 셋을 한 벌로 넣으면 '이사·팀장·사원'이 한 세트가 된다

## refs/ 는 뭔가

동현님이 원하는 **그림체 레퍼런스**를 모아두는 곳이다. PixelLab에 넣을 참고 이미지,
마음에 든 다른 게임 스크린샷 같은 것들. **앱은 이 폴더를 읽지 않는다.**
여기 있는 파일이 많아져도 위젯 동작에는 영향이 없다.

## 폴더 위치를 옮기고 싶으면

환경변수로 덮어쓸 수 있다.

```bash
CLAUDE_WATCHER_ART_DIR=/어디/다른/폴더 open -a claude_watcher
```

## ⚠️ 새 모션을 그리면 `anim.json`도 같이 고친다

`anim.json`에 적지 않은 상태는 **전 프레임을 반복한다.** 1번 프레임을
'들어가는 동작'으로 그려 두고 반복 구간을 안 적으면, 네 번에 한 번씩
가만히 선 모습이 껴서 동작이 끊긴 것처럼 보인다.

```json
{ "working": "2-4", "thinking": "2-4" }
```

2026-08-06에 thinking을 그려 넣고 이걸 빠뜨려서 실제로 그랬다.
확인은 `CLAUDE_WATCHER_SELFTEST=10` 으로 상태를 바꿔가며 화면을 떠서 본다.

## 아래 여백은 시트마다 따로 잰다

발이 상판에 붙는 위치는 **시트 전체에서 가장 낮은 픽셀**을 기준으로 맞춘다.
그래서 캐릭터를 캔버스 안에서 위아래로 옮겨 그려도 앱이 알아서 맞춘다.

다만 **상태끼리 '가장 낮은 픽셀'의 뜻이 같아야 한다.** idle은 발끝이
가장 낮은데 thinking은 몸통 선이 가장 낮으면, 그 차이만큼(지금 2px)
thinking이 살짝 잠긴 것처럼 보인다. 신경 쓰이면 발을 같은 높이로 그린다.


## 계층 모자 — `hats/`

계층(이사·팀장·사원)은 캐릭터 세트를 새로 그리는 대신 **모자로 가른다**(2026-09-15).

- `hats/director.png`(이사) · `hats/manager.png`(팀장). 사원은 모자가 없다 — 파일을 안 두면 된다
- 크기 64×32, 배경 투명. 그림의 **맨 아랫줄 가운데**가 캐릭터 머리 윗줄 가운데에 닿는다
- 머리 높이는 프레임마다 앱이 잰다. 캐릭터가 눌렸다 펴져도 모자가 따라간다
- 상태별 모자는 `director_working.png`처럼 상태 이름을 붙인다. 없으면 기본 한 장
- 모자는 시트로 자르지 않는다(64×32는 가로가 세로의 두 배지만 한 장으로 읽는다)
- 사람이 고른 캐릭터 세트를 쓰는 프로젝트에도 계층 모자는 얹힌다
